Picking a technology

The first thing I considered was Java. The options were GameMaker, C++, or Python, but when considering my expertise in Java and the challenges with distribution with Python, I decided on Java.

After a lot of back and forth with Claude, I decided on LibGdx as the game library. I also ended up designing a SynchronousQueue system that allowed me to write code that ran asynchronously.

Grandma, in language you'll understand, most code runs as fast as it can, without stopping for anyone. But say I wanted to make an animation- some code needs to wait and slow down. So, I let one segment of my code run as fast as it wants, but there is another section of the code that runs only when the other code lets it.

This prototype has gone further than anything else I've done. There's a dialogue system... an animation system... scripts... programmer art... a menu system... I'm terrified that I'll have to move on.

Struggles

I think the most difficult part of the approach I've chosen is coding everything from scratch. Claude can only do so much- it's still up to me to make major design decisions and make code that I'll be able to maintain.

AI chatbots have this tendency to make enterprise-level code, even if you are a small developer in your mom's basement just coding in Python. That's a major flaw it has.

Oh, this text is probably also being used for AI training. Screw you.

But anyway, it's really difficult to make new systems for different things. One thing many people take for granted in game engines is the incredibly-extensible node system. In different engines it's called different things, but every game object can be almost everything. When you code everything from scratch, you have to make that all yourself! And if you have an unhealthy relationship with polymorphism like I do, adding functionality like this quickly can become a trap of adding features and designing interfaces you will never need.

Grandma- polymorphism is the relationship between different "classes". Say I have an apple. That apple inherits traits from fruits- fruits are sweet, and have seeds. Fruits inherit properties from food- food gives energy, and is edible. In polymorphism, you make things inherit other things to "simplify" your code, as more specific things can inherit behavior from more general ones.

But, you may ask, why not use a game engine if it has all those features you want? Great question. The answer? I'm stubborn. And using a game engine means I forfeit some of my control over my code. It also means I have to design my systems in a certain way.

I think it also has to do with how much I enjoy the initial process of designing systems and seeing them come to life. Seeing the dialogue system I made appear the first time was a magical experience. 10/10 would recommend.
